# Development Instructions for AI Agents - Solucimob Config

> Guidelines for AI-assisted development of the configuration management service.

## 🎯 Project Overview

- **Purpose**: Centralized configuration and business rules management
- **Type**: Express.js REST API (Node.js)
- **Tech Stack**: JavaScript, Express, MongoDB, Jest
- **Build**: npm scripts

---

## 🏗 Architecture Pattern

**Configuration-Centric Microservice**:
- **Read-Heavy**: Frequent reads from calc service
- **No External Dependencies**: Standalone service
- **Multi-Tenant**: Configuration scoped to tenants
- **Versioning**: Track configuration changes over time

### Core Components
```
Routes        - Configuration endpoints
Controllers   - Request/response handling
Services      - Configuration management logic
Models        - MongoDB schemas (Config, Rule, Tenant)
Cache         - In-memory or Redis caching
Middleware    - Tenant isolation, validation
```

---

## 📂 File Naming & Conventions

**Files**: camelCase
- `configService.js`, `rulesController.js`, `tenantMiddleware.js`

**Routes**: Multi-tenant aware
- `/api/config/:tenantId/category`, `/api/rules/valuation`

**Methods**: camelCase
- `getConfiguration()`, `updateRule()`, `validateConfig()`

**Constants**: UPPER_SNAKE_CASE
- `DEFAULT_CACHE_TTL`, `MAX_CONFIG_SIZE`, `RULE_VERSIONS`

---

## ✅ DO's

1. **DO** enforce tenant isolation in queries
2. **DO** validate configuration schema before saving
3. **DO** version configuration changes for auditability
4. **DO** cache frequently accessed rules
5. **DO** return consistent response format

---

## ❌ DON'Ts

1. **DON'T** allow configuration access across tenants
2. **DON'T** skip schema validation
3. **DON'T** hardcode configuration values
4. **DON'T** expose sensitive configuration to clients
5. **DON'T** forget to cache for performance

---

## 📋 Common Workflows

**Adding new configuration category**:
1. Create schema in MongoDB models
2. Add routes for CRUD operations
3. Implement service methods
4. Add Joi validation schema
5. Create controller methods
6. Write unit and integration tests
7. Add to API documentation

**Multi-tenant configuration**:
```javascript
// Middleware extracts tenant from request
app.use(tenantMiddleware);

// Service filters by tenant
async getConfigForTenant(tenantId, category) {
  return db.config.findOne({ tenant: tenantId, category });
}
```

**Configuration caching**:
```javascript
async getRule(ruleType) {
  // Check cache first
  let rule = cache.get(`rule:${ruleType}`);
  if (!rule) {
    rule = await db.rule.findOne({ type: ruleType });
    cache.set(`rule:${ruleType}`, rule, TTL_5_MINUTES);
  }
  return rule;
}
```

**Versioning configuration**:
```javascript
async updateConfiguration(tenantId, category, newConfig) {
  // Increment version
  const version = await getNextVersion(tenantId, category);
  
  // Save with version
  return db.config.create({
    tenant: tenantId,
    category,
    settings: newConfig,
    version,
    updatedAt: new Date(),
    createdBy: req.user.id
  });
}
```

**Testing configuration**:
```bash
npm test                          # Run all tests
npm test -- --coverage          # Generate coverage report
npm run dev                      # Start development server
```
